# Milestone 7.2.5 — Single-File JSON Lesson Input

Goal: replace the multi-file JSON-and-CSV lesson package with one schema-validated JSON document,
remove CSV input infrastructure, and make one-command publishing the primary weekly workflow without
changing the SQLite knowledge model or Anki TSV output contract.

This is an intentionally breaking authoring-contract change between M7.2 and M7.3. The application
has not yet persisted lesson-package imports, so this is the last low-cost point to simplify the input
boundary before checksums, import history, and update behavior depend on it.

## Outcome

The generated input is one file:

```text
lesson.json
```

It contains the lesson, sources, vocabulary, sentences, grammar concepts, tags, provenance, and
relationships. CSV and pipe-delimited lists are not accepted as input. TSV remains the deliberate
output format for manual Anki import.

The normal completed-Milestone-7 workflow becomes:

```text
1. Generate or correct lesson.json.
2. tagalog lesson publish lesson.json
3. Manually import the generated Anki TSV files.
```

`lesson validate`, `lesson import`, `lesson show`, and `anki export` remain available as focused
diagnostic, correction, inspection, and retry commands. Import and publish always perform the same
validation internally; running `validate` first is never required.

## Contract decisions

- The input is a single UTF-8 JSON file named `lesson.json`.
- The new contract uses `schema_version: 2`; version 1 identified the former directory-plus-CSV
  representation.
- Only version 2 is supported after this migration. Do not retain a CSV compatibility loader,
  conversion mode, feature flag, or dual-schema branch.
- The top-level object requires `schema_version`, `lesson`, `sources`, `vocabulary`, `sentences`, and
  `grammar`. Entity arrays may be empty, but at least one of `vocabulary`, `sentences`, or `grammar`
  must contain a record.
- Optional values are represented by omitted properties. JSON `null` is not part of the contract.
- Tags, vocabulary references, and grammar references are JSON arrays. Pipe-delimited strings are not
  part of the contract.
- JSON property names, enum values, and UUID spelling are exact and case-sensitive. Unknown
  properties are invalid.
- All record UUIDs remain stable domain/database identities and Anki first-field identifiers.
- A missing entity-level `source_id` uses `default_source_id` when supplied. Source provenance remains
  lesson-association metadata rather than global entity identity.
- Package arrays have no semantic ordering. Tags and relationship arrays are duplicate-free sets for
  comparison and persistence purposes.
- String normalization, identity, duplicate-content, cross-package reference, conflict, update, and
  incremental-import rules remain unchanged from Milestones 6 and 7.
- The successful-import checksum is SHA-256 over the exact validated input bytes. Reformatting or
  reordering otherwise equivalent JSON produces a different package checksum but unchanged entity
  assessments; no JSON canonicalization layer is introduced.
- The input file limit is 25 MiB. Each entity array may contain at most 100,000 items, and each decoded
  string may contain at most 1,048,576 Unicode characters.

## Version 2 shape

```json
{
  "schema_version": 2,
  "lesson": {
    "id": "10000000-0000-4000-8000-000000000001",
    "name": "Pagbati at pagpapakilala",
    "description": "Greetings and introductions"
  },
  "sources": [
    {
      "id": "20000000-0000-4000-8000-000000000001",
      "name": "Course notes",
      "type": "COURSE",
      "reference": "Week 1"
    }
  ],
  "default_source_id": "20000000-0000-4000-8000-000000000001",
  "vocabulary": [
    {
      "id": "30000000-0000-4000-8000-000000000001",
      "tagalog": "kumusta",
      "english": "hello; how are you?",
      "part_of_speech": "INTERJECTION",
      "difficulty": "BEGINNER",
      "tags": ["conversation", "pagbati"]
    }
  ],
  "sentences": [
    {
      "id": "40000000-0000-4000-8000-000000000001",
      "text": "Kumusta ka?",
      "translation": "How are you?",
      "difficulty": "BEGINNER",
      "vocabulary_ids": ["30000000-0000-4000-8000-000000000001"],
      "grammar_ids": []
    }
  ],
  "grammar": []
}
```

Vocabulary properties are `id`, `tagalog`, `english`, optional `root_word`, `part_of_speech`, optional
`difficulty`, optional `frequency_rank`, optional `source_id`, and `tags`. Sentence properties are
`id`, `text`, `translation`, optional `difficulty`, optional `source_id`, `vocabulary_ids`, and
`grammar_ids`. Grammar properties are `id`, `name`, `description`, `formula`, and optional
`source_id`.

`tags`, `vocabulary_ids`, and `grammar_ids` are required arrays even when empty. This keeps generated
records structurally consistent and distinguishes collection fields from absent optional scalar
metadata. A missing `difficulty` defaults to `BEGINNER`.

## Diagnostics

Diagnostics identify the single filename plus a JSON path instead of CSV row and column coordinates.
Examples:

```text
lesson.json $.vocabulary[0].id: must be a lowercase canonical UUID
lesson.json $.sentences[1].vocabulary_ids[0]: vocabulary UUID does not exist
lesson.json $.grammar[0].formula: must not be blank
```

- JSON paths use zero-based array indexes because they identify the exact document location.
- Human-readable text may additionally say “vocabulary item 1” or “sentence item 2.”
- Stable JSON command output replaces `row` and `column` with `path`.
- Supplied values remain escaped, length-limited, and safe for terminal and JSON output.
- Syntax and structural errors may prevent entity conversion, but all independent semantic errors are
  still collected after successful structural parsing.
- Validation remains read-only and must not create a write transaction.

## Explicit non-goals

- Changing the SQLite schema or implementing M7.3 persistence.
- Changing global entity identity, lesson association, source provenance, or incremental update rules.
- Replacing TSV output, generating `.apkg` files, or adding AnkiConnect.
- Supporting JSON and CSV input simultaneously.
- Supporting YAML, Markdown, JSON Lines, archives, URLs, or standard input as lesson-package input.
- Supporting multiple lessons in one input file.
- Implementing `lesson publish`; this milestone defines its simplified interface and updates the M7.6
  plan, while M7.6 implements the composition after import and export services exist.
